# Воспроизведение виртуальной кампании M9

## Зафиксированная конфигурация

- Кампания: `M9-RC-2026-01`, протокол `M9-campaign-v1.2`.
- Сценарии и критерии: `07_Испытания/campaign.yaml`; соответствие семействам V01–V15: `07_Испытания/Матрица_сценариев.csv`.
- Среда: CPython 3.12.10, MuJoCo 3.14.0, зависимости с закрепленными версиями из `04_Программа/integration/requirements.txt`.
- Основной профиль: `nominal`; batch mode; видеозапись выключена для приемочных запусков.
- Seed, параметры, полная команда, хеш кампании, снимки входов и итоговые данные записываются в `07_Испытания/campaign_state.jsonl`, `campaign_metadata.json`, `runs/<run_id>/campaign_trial.json` и `manifest.json`.
- Первичные логи сохраняются без потерь. Крупные CSV/JSONL и M5 JSON-планы сжимаются gzip; исходный и сжатый SHA-256 сохраняются в записи прогона. Анализатор проверяет целостность перед расчетом метрик.

Все приведенные ниже проверки относятся к программной симуляции MuJoCo; команда не выполняет физические измерения.

## Чистая среда Windows PowerShell

Из корня репозитория создайте отдельное окружение и установите закрепленные зависимости:

```powershell
py -3.12 -m venv .venv
$py = '.venv/Scripts/python.exe'
& $py -m pip install --upgrade pip
& $py -m pip install -r '04_Программа/integration/requirements.txt'
$env:PYTHONPATH = (Join-Path (Get-Location) '04_Программа')
$env:PYTHONDONTWRITEBYTECODE = '1'
```

Проверьте M9-инструменты и план кампании, не запускающий симуляции:

```powershell
& $py -m unittest discover -s '05_Верификация/integration/tests' -p 'test_m9_*.py' -v
& $py '04_Программа/run_m9_campaign.py' --dry-run
```

Dry run должен показать 98 уникальных заданий и SHA-256 протокола. Он не является частью испытательной выборки.

## Запуск или продолжение кампании

Полный зарегистрированный запуск:

```powershell
& $py '04_Программа/run_m9_campaign.py'
```

При остановке процесса повторите ту же команду: завершенные задания с тем же хешем протокола и сохраненными логами будут пропущены, остальные продолжатся. Не меняйте `campaign.yaml` во время приемочной серии. При исправлении кода после запуска сохраните старые данные, создайте новую версию протокола и запускайте затронутую серию заново под отдельным каталогом/файлом состояния.

Запуск отдельного `--trial-id` допустим только как диагностика или повтор зарегистрированного задания. Он не заменяет полный набор и не дает права объявлять кампанию завершенной.

## Пересчет таблиц и графиков

После всех 98 заданий:

```powershell
& $py '04_Программа/analyze_m9.py'
```

Анализатор по каждому `campaign_trial.json` проверяет зарегистрированные поля, ID, seed, manifest hash, campaign hash, хеши файлов входной модели и исходные/сжатые evidence-хеши. При отсутствующем, поврежденном или незарегистрированном прогоне расчет останавливается, а не скрывает его. Таблицы сохраняются в `07_Испытания/tables/`, графики — в `07_Испытания/plots/`, агрегат — `07_Испытания/campaign_results.json`.

## Повторяемость V14

Оставьте исходные логи V03 seed `20261001` и `v14_repeat_seed_20261001` несжатыми до сравнения:

```powershell
& $py '05_Верификация/integration/compare_m7_runs.py' `
  '07_Испытания/runs/<run_id_V03_seed_20261001>' `
  '07_Испытания/runs/<run_id_V14_repeat_seed_20261001>' `
  --output '07_Испытания/tables/Проверка_повторяемости_V14.json'
```

Если `accepted` равен `true`, сохраните отчет и сожмите повторяемую пару:

```powershell
& $py '04_Программа/run_m9_campaign.py' --compress-verified-repeatability-pair
```

После сжатия повторно выполните анализатор: контроль целостности должен пройти и для gzip-логов.

## Запись и проверка демонстрационного видео

В кампании `v01_red` оставляется несжатым как заранее назначенный источник parity-проверки. После подтверждения успешного исхода запишите тот же встроенный сценарий `single_red_center` в отдельный каталог:

```powershell
& $py '04_Программа/run_m7.py' --mode batch --scenario single_red_center `
  --physics-profile nominal --record `
  --out '07_Испытания/recording_parity/runs' `
  --recording-out '06_Медиа/M9'
```

Сверьте зарегистрированный `v01_red` и повтор с записью; берите run ID из их `manifest.json`:

```powershell
& $py '05_Верификация/integration/compare_m7_runs.py' `
  '07_Испытания/runs/<registered_v01_red_run_id>' `
  '07_Испытания/recording_parity/runs/<recorded_run_id>' `
  --output '06_Медиа/M9/<recorded_run_id>/Сверка_с_записью.json'
```

Перед использованием MP4 проверьте его полное декодирование и свяжите медиа-манифест с зарегистрированным сценарием, seed, исходным run ID и parity-отчетом. Видео должно называться виртуальной симуляцией, а не физическим испытанием.

## Повторное развертывание на новом ПК

Сохраните версию Python, зависимости, Git revision, `campaign.yaml`, конфигурацию SSOT и все run manifests. Для новой независимой кампании задайте новый пустой `--out` и отдельный `--state`; не дописывайте повторный эксперимент поверх уже принятого набора. Результаты новой ревизии анализируйте отдельно и обозначайте новый campaign hash.
