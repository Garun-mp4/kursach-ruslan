## 1. Входная конфигурация и модель

- Использована геометрия SSOT `M2-v1.0`; рабочий файл SSOT теперь имеет `config_version: M3-v1.0` и `geometry_baseline_version: M2-v1.0`. Ни одна геометрическая величина M2 не менялась.
- Верификационный отчет зафиксировал SSOT SHA-256 `733b6fa5c0c5ef9c022c0cfc0922d24668b944ed84758de2ce78fe374b1c2651` и компилируемую модель MJCF SHA-256 `d5445d8a6a4cf1a38f533be697d6cd0748d457e4de40d6a16d5240752957c9e2`.
- Манипулятор — SCARA R–R–P–R, порядок `q=[q1_rad,q2_rad,q3_m,q4_rad]`. Пределы: J1/J4 ±π, J2 ±150°, J3 0…0,097 m.
- Опорные кадры: `BASE`, `J1`, `J2`, `J3`, `J4`, `TCP`; `BASE` совмещена с WORLD по XY baseline. Используются однородные матрицы 4×4 для векторов-столбцов, композиция от BASE к TCP.
- Цепочка: `BASE→J1: Txyz(shoulder)Rz(q1)`; `J1→J2: Tx(L1)Rz(q2)`; `J2→J3: Tx(L2)Tz(−q3)`; `J3→J4: Tz(−0,075)Rz(q4)`; `J4→TCP: Tz(−0,012)`. Отдельные angular zero offsets не задаются: `q` совпадает с координатами MuJoCo joint при стандартном `ref=0`; пространственные смещения кадров ненулевые и явно берутся из SSOT.

## 2. Реализация FK/IK и диагностик

- FK реализован вручную через матрицы; модуль `scara.py` не импортирует MuJoCo и не зависит от GUI/FSM.
- TCP учитывает wrist offset −0,075 m и tool offset −0,012 m. Положительный ход J3 направлен вниз (−Z); формула высоты: `z_TCP=0,103−q3`.
- FK формулы: `x=xb+L1 cos q1+L2 cos(q1+q2)`, `y=yb+L1 sin q1+L2 sin(q1+q2)`, `z=zb+0,103−q3`, `yaw=wrap(q1+q2+q4)`.
- IK аналитическая для двух планарных ветвей: `q2=±acos(c2)`; `q1` рассчитан через два `atan2`; `q3` определяется TCP Z; `q4` компенсирует суммарный yaw. Кандидаты J1/J4 перечисляются по периодическим представителям, но сохраняются только при соответствии физическим limits. J2 не приводится к диапазону wrap-операцией.
- Геометрическая недостижимость, выход J2/J3, невозможность ориентации, невалидная цель/текущее состояние и numerical residual failure имеют отдельные статусы. Кандидат не принимается при превышении заданного FK допуска.
- У квадратного объекта разрешены четыре yaw-представления с шагом π/2; режим exact-tool-yaw доступен при отключенной симметрии.
- Branch cost — квадрат суммы прямых суставных смещений, каждое делится на полный допустимый ход соответствующей оси. Метры и радианы тем самым сопоставляются безразмерно. Далее применяется детерминированный tie-break: regular, запас до предела, стабильный порядок ветвей/симметрий.

## 3. Сингулярности и численные допуски

- Плоская кинематическая сингулярность возникает при `sin(q2)=0`: straight `q2=0` достижима, folded `q2=±π` исключена лимитом J2.
- Near-singularity threshold: `|sin(q2)|≤0,05`, состояние маркируется, но не отклоняется. На q2=0,05 rad: `σ_min=0,00484938 m/rad`, condition number `97,7631`, локальное усиление `206,212 rad/m`.
- Якобиан проверен central finite differences: 200 конфигураций, seed 52103, шаг 1e−7, максимум абсолютной ошибки компонента `6,0775e−9`.
- До основной верификации в SSOT записаны: cos round-off `1e−12`; revolute/prismatic limit tolerances `1e−12 rad`/`1e−12 m`; candidate dedup `1e−12` в нормированных единицах; position acceptance `1e−6 m`; yaw acceptance `1e−8 rad`; near-singular порог `0,05`.

## 7. Найденные ошибки и исправления

1. Первоначальная оценка углового расхождения через `acos(trace)` давала искусственную ошибку порядка `3,65e−8 rad` из-за потери точности около identity. Заменена устойчивой `atan2(skew norm, cosine)` формой; независимый parity повторен.
2. Boundary sampler приводил периодическое q1 к представителю вне физических ±π. Выборка теперь сохраняет представителя внутри лимита; граничная ведомость построена заново.
3. При аудите выяснилось, что acceptance tolerances были объявлены в SSOT, но код не прекращал успех при превышении остатка. Добавлена явная проверка FK position/yaw остатка и статус `NUMERICAL_FAILURE`; fault-injection regression test подтверждает поведение.
4. Первый вариант новой regression fixture использовал неверное имя поля `frames`; исправлено на `frames_base`. Ошибка относилась только к тестовой заготовке, после исправления все 23 теста проходят.

После исправления acceptance guard полный воспроизводимый verifier пройден снова: `PASS`, source hash `0d8cc8063e91543d7bbe99ef2113a8698de600cac50f101a1225c10b27b0496a`. Основные численные результаты остались в пределах прежних значений; geometry/MJCF hash не изменились.
