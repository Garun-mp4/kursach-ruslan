Поток одного цикла: обслуживание запроса и получение RGB → perception M4 → решение контроллера M6 → M5-план по запросу → конечные MuJoCo-приводы → интегрирование физики → touch/encoder feedback и телеметрия. Эталонная поза, цвет, внутренний ID тел и evaluator-контакты недоступны контроллеру. Независимый evaluator получает ground truth только после окончания контроллера.

Захват выполняется конечными позиционными приводами и динамическими контактами MuJoCo. Искусственного weld/attach, телепортации объекта или скрытого snap к лотку нет. Укладывание подтверждается новым публичным RGB-изображением после отвода манипулятора, а окончательный физический результат определяет post-run evaluator.

## 2. Исправления и интеграционные решения M7

1. Добавлена отдельная публичная камера placement_rgb для лотков. Она использует RGB, свою калибровку и общий perception-код; тест покрывает все 3 класса × 3 слота.
2. Добавлена управляемая инъекция устаревшего входного RGB-кадра. Три повторно выданных старых кадра с новым frame ID сохраняют старую simulation timestamp и отвергаются M4/M6 по возрасту.
3. Устранено совместное использование runtime и GUI одного MjModel/MjData. Интерактивное окно получает снимки в отдельную модель и данные; его pause/scrub/reset не могут менять интегрируемое физическое состояние.
4. Исправлено поведение при закрытии окна: runtime отсоединяет display и продолжает расчёт без viewer до завершения или штатного SAFE_STOP.
5. Добавлены измерения wall-time управляющего цикла, отдельного mj_step, двух RGB-рендеров, perception и viewer.sync. Wall timers не входят во вход контроллера и не меняют simulation clock.
6. Добавлен compare_m7_runs.py для повторяемого сравнения манифестов, входных хешей, RGB snapshots, событий, планов, телеметрии, evaluator и конечного состояния.
7. Отчёт, реестр рисков и матрица требований обновлены с прежних M7-v1.5 значений. Исторический mixed результат 2/3 сохранён отдельным run `mixed_random_three-085b3ee4c4`; причина его отличия от текущей серии не выводится только из нового успешного результата.

## 5. Отказы и безопасные исходы

Полная интеграционная регрессия охватывает 35 тестов; все пройдены. Ключевые отрицательные сценарии:

| Сценарий | Наблюдаемый виртуальный исход |
|---|---|
| Невалидный кадр камеры | После трех последовательных невалидных наблюдений SAFE_STOP/CAMERA_FAILURE_LIMIT до запуска движения |
| Устаревший RGB | 3 кадра со статусом STALE; SAFE_STOP на 0.03 s; команда приводу не выдана |
| Невалидный placement view | Нет публичного подтверждения укладки; успех не засчитывается |
| UNKNOWN-цвет | Класс сохраняется как UNKNOWN; объект пропускается без захвата |
| Полная зона | Занятость выявлена публичным RGB; объект пропущен, попытки захвата нет |
| Заблокированный/недостижимый подход | M5 отказывает до движения, M6 классифицирует безопасный skip |
| Нулевая сила привода захвата | Таймаут tracking; успешный захват не заявляется |
| Очень низкое трение | Подъем не подтверждает удержание; SAFE_FAILURE/SAFE_STOP |
| Потеря удержания импульсом во время transfer | Потеря public hold обнаружена; SAFE_STOP, ложной сортировки нет |
| Аварийный стоп при удержании | SAFE_STOP/EMERGENCY_STOP; holding_state=true, no_automatic_release=true; груз остаётся поднятым в терминальном состоянии модели |
| Отказ привода раскрытия | SAFE_STOP/SAFE_FAILURE. Хотя физическая модель случайно оставила объект в целевом слоте, контроллер не подтверждает сортировку |
| Численный дрейф контакта | Регрессия подтверждает настроенный NoSlip режим; это численное свойство модели, не измерение реального материала |

Физическое размещение определяется после окончания управления; внутренний статус DONE сам по себе не равен успеху. Условие controller_done_and_physical_success требует одновременно завершения FSM, подтверждения всех объектов контроллером и независимой проверки каждой фактической зоны.

Один и тот же однообъектный RED сценарий повторён с актуальной SSOT и кодом M7-RC. Это локальная чувствительность выбранной позы, а не статистическая кампания.

Профиль coarse_timestep 0.005 s не запускался: анализ M1 уже выявил нестабильность контакта на грубом шаге. Основание и ограничения записаны в m7_physics_profile_comparison.json.

## 10. Исправленные дефекты и версионная оговорка

- Исходный M7-v1.5 mixed seed имел исход 2/3: GREEN был безопасно отвергнут с BRANCH_DISCONTINUITY. Репрезентативный исходный run `mixed_random_three-085b3ee4c4` сохранён. В M7-v1.8 два повтора того же seeded mixed scenario дали 3/3. Причина разницы не приписывается конкретному изменению без отдельного сравнительного анализа версий; широкую устойчивость должен определить M9.
- Найденная при интерактивном запуске регрессия shared MjData приводила к simulation-time regression; GUI и runtime разделены, свежая parity-пара совпала полностью.
- Закрытие display во время длительного вызова больше не оставляет controller на промежуточном состоянии; timed-close run завершился с физически проверенным результатом.
- Ранее отсутствовавшая возможность строго проверить stale RGB закрыта инъекцией старого буфера и отдельным тестом.
- Предыдущий M07.md содержал старые версии, run IDs, 121 тест и устаревший исход mixed-run; он заменён текущим отчётом.

## 11. Ограничения и границы milestone

- Это виртуальная динамическая модель, а не собранный робот; реальные материалы, моторы, допуски, камера и аварийная электроника не измерялись.
- Контактные коэффициенты, массы/инерции и NoSlip являются параметрами и допущениями модели.
- Успех трёх одноцветных поз и двух повторов одного mixed seed не является статистическим доказательством общей эффективности или универсальной достижимости.
- Wall-time зависит от ПК, графического backend и загрузки системы; иная машина не проверялась.
- Memory sample включает только два соседних запуска.
- Прежний M7-v1.5 mixed fail не скрыт, но его точный источник изменения не установлен. Повторные и отладочные прогоны сохранены как сырые локальные данные; они не используются для численных выводов этого отчёта.
- MP4/визуальная упаковка относится к M8; статистическая приемочная кампания — M9. Они в рамках M7 не выполнялись.
