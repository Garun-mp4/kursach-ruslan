## Камера и sensor contract

Используется M2 overhead camera: position `[0,0,1.05] m`, quaternion `[1,0,0,0]` (wxyz), vertical FOV `50°`, resolution `640×480`, `fx=fy=514.6816609 px`, `cx=319.5 px`, `cy=239.5 px`. Renderer image is RGB uint8. `CameraFrame` carries frame ID, simulation timestamp, camera configuration ID and validity. Maximum age is `0.04 s`; missing, stale, malformed, wrong-camera or future frames yield an empty batch (`NO_FRAME`, `STALE` or `INVALID`), never the previous pose.

Channel order was checked using synthetic RGB primaries and an actual MuJoCo-rendered red surface (mean `[254.64,65.80,57.92]`); explicit OpenCV conversion is `COLOR_RGB2HSV`. OpenCV HSV Hue primaries were `0/60/120` on the 0…179 scale.

## Detection, classification and pose

The independent detector compares the RGB frame with a static background in Lab (`ΔE*ab≥16`), applies per-channel median normalization, restricts candidates to the input ROI and excludes all three sorting-zone polygons. A 3×3 opening, area/aspect filtering, and external contours form candidate masks. A large contour splits only when at least two separable valid RGB color cores are present; otherwise it is rejected as `OCCLUDED`.

Frozen HSV ranges (OpenCV scale): RED `0…7` or `176…179`, GREEN `57…69`, BLUE `108…121`, with class-specific saturation/value floors. Hue wrap is explicitly handled. Other/ambiguous colors stay `UNKNOWN`. Confidence is a bounded mask-coverage/class-margin score, not calibrated probability. A future pick consumer must require `status==VALID` **and** a supported class RED/GREEN/BLUE; `UNKNOWN` is never a pick command.

XY uses a color-core minimum-area rectangle center; yaw uses the long edge after mapping the contour to BASE. Square symmetry is π/2 and the canonical yaw range is `[0,π/2)`. Tracking is deterministic nearest-neighbour in XY (`0.055 m`, two missed frames); IDs are generated by the tracker and contain no simulator object ID.

## Calibration and coordinate error

The calibration is planar homography `M4-HOMOGRAPHY-TOP-PLANE-v1.1`, from image pixels to BASE coordinates on the object top plane `z=0.016 m`. It is not a general 3-D reconstruction. There are 49 fit points and 64 spatially distributed independent validation points. Independent validation: mean planar error `0.277 mm`, p95 `0.512 mm`, maximum `0.879 mm`; RMSE X/Y `0.259/0.190 mm`. Calibration artifact includes both homographies, intrinsics, point sets, residuals and version.

Only isolated `28×28×16 mm` cuboids on the fixed plane are supported. A ±1 mm unmodelled height change is estimated to contribute up to about 0.37 mm radial scale error near the ROI edge; other heights, stacking and piled objects are outside scope.

Pose errors are reported separately from detection/classification. For the 353 supported-color poses, XY mean/median/p95/max are `0.437/0.394/0.891/1.361 mm`; yaw p95/max are `4.019°/6.647°`. They meet the M4 allocation of `2 mm XY` and `10° yaw` within this virtual domain.

There are 12 `VALID` UNKNOWN geometry poses, which remain non-pickable. Their XY mean/p95/max are `1.648/2.158/2.178 mm`; two exceed 2 mm. The largest XY residuals are UNKNOWN cases (seed 20265052: 2.178 mm; seed 20265020: 2.141 mm). These errors are retained, not hidden. Three more low-contrast UNKNOWN objects are out of the declared visibility domain and receive `OCCLUDED`, so they are not pose-valid pick targets. Among all 365 pose outputs, p95 XY is `1.042 mm`, maximum `2.178 mm`; the overall maximum must not be presented as if every candidate meets 2 mm.

M2 total planar grasp budget is `4 mm`; the arithmetic remainder after the aggregate perception p95 is `2.958 mm`. This is not a proof of contact/actuator success or a worst-case sum. M7 must evaluate the integrated grasp. The real camera is not tested.

## Stress cases and controlled failure

- 36 blank scenes (3 illumination levels × 3 noise levels × 4 repeats): no candidates.
- All three static sorting zones excluded.
- Neighbours with 8 mm gap and touching faces: two independent poses in both checks.
- Partial/arm occlusion: `OCCLUDED` or empty detections; no reuse of stale target.
- Missing/stale/malformed/wrong-camera/future timestamp: fail closed with empty detections.
- RGB noise/illumination changes, shade variants, rotated placements and low-contrast UNKNOWN are represented in stored fixtures/manifests.
- Invalid or unsupported appearance does not get forced into RED/GREEN/BLUE.

## Data-boundary audit

Perception runtime has no import/access path to MuJoCo model/data, rig, evaluator, true pose, true color, simulator object name/ID or segmentation buffers. The frame type contains only rendered RGB and sensor metadata. Ground-truth is kept in evaluator-side manifests and used only to score outputs. Static AST audit: 0 forbidden references. This verifies the M4 runtime boundary; the full integrated controller/evaluator path still requires the planned M7 audit.

## Defects found and resolution

During iterative development, early versions exposed three classes of weaknesses: low-contrast UNKNOWN masks could disappear or create background false candidates; merged masks could hide adjacent known-color objects; and acceptance/reporting initially conflated candidate pose error with pick-eligible supported-color pose error. The final profile uses 3×3 morphology and 8 px² minimum area selected against tuning plus blank-scene data, splits a merged contour only when multiple separable RGB cores exist, otherwise rejects it, and reports errors separately by class/status/domain. Earlier diagnostic runs are retained in named archive folders and are not treated as final acceptance data. A stale M3-version parser and old test-call signatures were fixed before the canonical independent run. The confusion-matrix label layout was corrected and all analysis images regenerated.

## Forward compatibility (without starting later milestones)

- **M5:** perception provides fresh `VALID` supported-class `xy_base_m`, `yaw_base_rad`, quality, uncertainty, frame/time, and track ID; the planner can consume a pick pose without inferring sensor pins or truth data. This is interface compatibility only; no planner is implemented here.
- **M6:** UNKNOWN, OCCLUDED, NO_FRAME, STALE and INVALID are explicit fail-closed outcomes. The retry/safe-state policy remains to be implemented there.
- **M7:** fixed plane, gripper footprint, XY/yaw measurements and exclusions are documented; integrated contact/grasp, vertical J3 margin and end-to-end evaluator isolation remain open there.
