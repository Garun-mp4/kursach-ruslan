**Версия политики контроллера:** `M6-v1.0`

## 2. Набор состояний и переходы

Полный state model содержит 16 состояний. Базовые операции цикла разнесены на более мелкие состояния, чтобы отдельно контролировать захват, удержание, отпускание, восстановление и безопасную остановку.

| State | Роль и граница перехода |
|---|---|
| `INIT` | Проверяет SSOT, зависимости, arm/gripper readiness, свежесть начальных измерений и отсутствие зависших резервов; далее `OBSERVE` либо `SAFE_STOP`. |
| `OBSERVE` | Принимает только новый согласованный M4 кадр; далее `SELECT`, `DONE` после подтвержденной пустой сцены либо `SAFE_STOP`. |
| `SELECT` | Проверяет кандидатов и свободные слоты, затем атомарно резервирует track и slot; далее `PLAN`, `OBSERVE`, `DONE` либо `SAFE_STOP`. |
| `PLAN` | Запрашивает полный цикл у M5; далее `APPROACH`, `RECOVER` для классифицированного отказа либо `SAFE_STOP`. |
| `APPROACH` | Выполняет только начальный подход и pregrasp фазы принятого M5 плана; далее `DESCEND`, `RECOVER` или `SAFE_STOP`. |
| `DESCEND` | Выполняет M5 descent; далее `GRASP`, `RECOVER` или `SAFE_STOP`. |
| `GRASP` | Командует закрытие пальцев; само закрытие не доказывает захват; далее `VERIFY_HOLD`, `RECOVER` или `SAFE_STOP`. |
| `VERIFY_HOLD` | Выполняет тестовый подъём и требует свежих разрешённых hold-сигнала и M4 наблюдения источника; далее `TRANSFER`, `RECOVER` или `SAFE_STOP`. |
| `TRANSFER` | Переносит груз, непрерывно проверяя свежее удержание; далее `PLACE` либо `SAFE_STOP`. |
| `PLACE` | Опускает груз только в принадлежащий текущему track зарезервированный слот; далее `RELEASE` либо `SAFE_STOP`. |
| `RELEASE` | Выполняет отпускание только после завершения placement descent; требует свежего empty-gripper подтверждения; далее `VERIFY_PLACE` либо `SAFE_STOP`. |
| `VERIFY_PLACE` | Требует новый public-camera perception результат с классом, зоной, слотом и порогом confidence; далее `RETREAT`, `RECOVER` либо `SAFE_STOP`. |
| `RETREAT` | Выполняет M5 retreat/safe return/home и закрывает цикл; далее `OBSERVE`, `RECOVER` либо `SAFE_STOP`. |
| `RECOVER` | Выполняет только ограниченное действие, разрешённое известным контекстом и подтвержденным состоянием без груза; далее `OBSERVE` либо `SAFE_STOP`. |
| `SAFE_STOP` | Защёлкнутая остановка: нет новых движений или автоматического раскрытия. Только явный операторский reset с разрешением исхода груза может вернуть автомат в `INIT`. |
| `DONE` | Терминальное завершение обработки batch; не является утверждением о 100% правильной сортировке. |

Базовая функциональная последовательность реализована явно как `INIT → OBSERVE → SELECT → PLAN → APPROACH → DESCEND → GRASP → VERIFY_HOLD → TRANSFER → PLACE → RELEASE → VERIFY_PLACE → RETREAT → OBSERVE`. Восемь уточнённых состояний (`DESCEND`, `VERIFY_HOLD`, `TRANSFER`, `RELEASE`, `VERIFY_PLACE`, `RETREAT`, `RECOVER`, `SAFE_STOP`) выделены для межфазных safety gates и обработок отказа; `DONE` выделен как самостоятельный terminal outcome. M0–M5 не фиксировали более подробный нормативный enum состояний.

В коде и таблице `TRANSITIONS` задано **39 разрешённых дуг**. Реализация `_transition()` отклоняет любую иную дугу через `IllegalTransitionError`. Диаграмма показывает замкнутый основной цикл из 13 рабочих состояний, включая возврат `RETREAT → OBSERVE`; ветви отказа и все точные разрешённые дуги перечислены в `FSM.md` и `transition_coverage.csv`, а не скрыты за эвристикой диаграммы.

Временные состояния ограничены по simulation time. Для терминальных `DONE` и защёлкнутого `SAFE_STOP` таймер перехода не нужен: выход возможен только по терминальной семантике или явному безопасному reset. Движение не зависит от render FPS или wall-clock ожидания.

| Таймер/лимит из SSOT | Значение и смысл |
|---|---|
| `init_timeout_s` / `observation_timeout_s` / `select_timeout_s` | 0,5 / 0,25 / 0,5 s simulation time |
| `plan_response_timeout_s` | 120 s simulation time; отдельно действует M5 compute wall-time cap 90 s |
| `recovery_timeout_s` | 5 s simulation time |
| `hold_verification_timeout_s` / `place_verification_timeout_s` / `gripper_release_confirmation_timeout_s` | 0,25 / 0,5 / 0,25 s simulation time |
| Исполнительные состояния | `max(1,0 s, длительность соответствующих фаз M5 × 1,5 + 2,0 s)`; полный cycle deadline `длительность плана × 1,5 + 30 s` |
| `batch_timeout_s` | 1800 s simulation time |
| Максимальный возраст hold evidence | 0,04 s simulation time; унаследовано от M4 sensor freshness |
| Пустая сцена / UNKNOWN | 3 разных свежих пустых кадра / 2 разных свежих UNKNOWN наблюдения |
| Ошибки камеры / частичная сцена | 3 подряд ошибки / 3 разных свежих кадра неопределённости |
| Повторы | M5 retry: 1 на track; grasp attempts: 2 всего на track; cycle attempts: 2 на track; recovery: 1 на action/episode с reset после подтвержденного recovery |

Все значения, единицы, владельцы и происхождение записаны в SSOT; controller загружает их из конфигурации. Это рабочие controller budgets, а не измеренные параметры динамики.

## 3. Выбор объектов, зоны и резервации

1. Контроллер принимает только свежие и согласованные M4 оценки. Повторяющиеся observations одного track ID объединяются; конфликтующие дубликаты закрывают выбор fail-closed.
2. `UNKNOWN` не получает class-to-zone mapping. Он остаётся кандидатом для двух отдельных свежих наблюдений и после подтверждения отмечается `SKIPPED_UNKNOWN`.
3. Для известных классов зона и порядок доступных слотов берутся из SSOT. В текущей конфигурации `BLUE/GREEN/RED` соответствуют одноимённым зонам, каждая имеет три slots `CLASS:0..2`.
4. SELECT оценивает качество классификации, нормированную XY/yaw неопределённость, оценочную стоимость XY перемещения и прошлые безопасные отказы. Меньший score лучше:

   `0.40·(1−confidence) + 0.20·xy_uncertainty + 0.10·yaw_uncertainty + 0.25·motion_cost + 0.05·failure_history`.

   Компоненты uncertainty/motion нормируются по M6 конфигурации; это ранжирование, не feasibility verdict. Только M5 устанавливает достижимость. При равенстве выбирается меньший M4 `track_id`, поэтому решение детерминировано.
5. Track и первый свободный slot резервируются до запроса плана и до движения. Полная зона обрабатывается до захвата; контроллер не запускает M5 план и не выдумывает успешную укладку.
6. При неуспешном цикле резервации освобождаются до обработки следующей цели, если payload безопасно подтверждён как отсутствующий. Занятый после подтверждения слот не освобождается. Неоднозначный/ошибочный исход переводит слот в `QUARANTINED`. При SAFE_STOP с удерживаемым или неизвестным грузом активная резервация сохраняется.
7. После исчерпания `max_cycle_attempts_per_track=2` проблемная цель помечается с причиной и более не блокирует выбор следующих допустимых объектов. Это проверено controlled случаем «ошибочная/недостижимая цель + допустимая цель».

## 4. Передача плану M5, захват и подтверждение укладки

M6 не реализует кинематику и не строит скрытый планировщик. Для активного M4 track и зарезервированного slot он формирует `PlanRequest` к M5. До `APPROACH` проверяются target/class/slot, SSOT и model hashes, исходный perception frame/time, конечность samples и timestamps, положительная согласованная длительность, полный упорядоченный набор фаз и правильные attachment/release markers. Любое движение запрещено до полного `SUCCESS`.

Переход к переносу возможен только после завершённой M5 фазы `LIFT` и двух согласованных публичных признаков: свежий `FINGER_CONTACT_SENSOR` либо `GRIPPER_EFFORT_PROXY` с `holding=True`, а также новый M4 кадр, где объект больше не наблюдается в исходной позиции. Достоверность закрытой команды пальцев, истинная поза объекта и evaluator contact не используются. Hold сигналы старше 0,04 s, не имеющие допустимого источника или противоречащие кадру не подтверждают захват; неизвестный hold после timeout приводит к безопасной остановке.

Переход в `TRANSFER` невозможен без такого verified hold. Во время переноса и перед placement удержание перепроверяется; потеря или устаревание сигнала приводит к `SAFE_STOP` и сохранению состояния резервации, без повторного захвата вслепую.

Controller-level placement подтверждается только свежим кадром **после** release от `PUBLIC_CAMERA_PERCEPTION`: status `CONFIRMED`, совпадающие ожидаемые class/zone/slot и confidence не ниже 0,75. Тогда создаются `PLACED_CONTROLLER_CONFIRMED` и `OCCUPIED`. Это не evaluator truth и не доказательство реального физического успеха. M4 camera ROI сейчас не включает лотки; M7 обязан подключить отдельный public placement-perception adapter/view. До этого production placement confirmation не интегрирован.

## 5. Ошибки, восстановление и учёт исхода

Таблица `Матрица_ошибок_и_реакций.csv` содержит 20 уникальных error/event строк, наблюдаемые условия, реакцию, работу с reservation, reason/event codes, retry/escalation и M7 примечания. Основные классы:

- Временные `TIMEOUT`, `STALE_DETECTION`, `SCENE_UNCERTAIN` от M5 допускают максимум один повтор только после нового perception кадра.
- `INVALID_INPUT`, `INVALID_BATCH`, `MODEL_MISMATCH` являются fatal и приводят к `SAFE_STOP`.
- `NO_AVAILABLE_SLOT`, `SLOT_INVALID`, `SLOT_OCCUPIED` не разрешают захват; проблемное место не переиспользуется без проверки.
- Постоянная невозможность цели переводит track в `SKIPPED_UNREACHABLE`, очищает его reservation при безопасном no-payload состоянии и позволяет выбрать следующую цель.
- Ошибка камеры/сцены ограниченно повторяется; UNKNOWN не принуждается к известному цвету; пустой валидный кадр отличается от отказа камеры.
- Подтверждённый no-hold может разрешить один безопасный recovery/retry. При held/unknown payload, потере объекта, конфликте контракта, исчерпанном recovery или emergency команда движения отменяется, причина защёлкивается, захват автоматически не раскрывается.

`RECOVER` выбирает действие по контексту: планировщикский отказ без движения может завершиться без motion recovery; неуспешный grasp требует публично подтвержденного no-hold; неопределённое удержание не позволяет открыть gripper; ошибка отхода после release не повторяет release. Recovery должен завершиться с подтвержденным arm/gripper state за 5 s и укладывается в бюджет 1 попытки. После успешного recovery его budget сбрасывается.

| Уровень результата | Статусы | Смысл |
|---|---|---|
| Track | `PENDING`, `RESERVED`, `PLACED_CONTROLLER_CONFIRMED`, `SKIPPED_UNKNOWN`, `SKIPPED_UNREACHABLE`, `SKIPPED_FULL_ZONE`, `SAFE_FAILURE` | Отдельный lifecycle, причина пропуска/отказа и счётчик попыток; пропуск не является сортировкой. |
| Slot | `FREE`, `RESERVED`, `OCCUPIED`, `QUARANTINED` | `OCCUPIED` только после подходящего публичного evidence; неопределённое место не объявляется свободным. |
| Batch | `DONE`, `SAFE_STOP` | `DONE` означает завершённую обработку, а не долю правильно отсортированных предметов. |
| Независимый evaluator | Отдельные truth labels и контакты | Не доступен контроллеру; итоговая truth-level оценка принадлежит M9. |

## 6. События, инварианты и граница ground truth

Решения записываются типизированными `ControllerEvent` с run-scoped идентификаторами, simulation time, state, reason code, track/slot и event-specific details. Таксономия генерируется из мест `_emit` в `controller.py` и сохранена в `event_taxonomy.csv`. Отчёт телеметрии M9 заранее фиксирует поля для state sequence, ошибок, повторов, object lifecycle и timing.

Автоматически после каждого штатного `step()` проверяются инварианты: максимум одна согласованная пара track/slot reservation; track status и reservation owner совпадают; `TRANSFER`/`PLACE` требуют свежего hold; `PLACE` требует правильный slot; подтвержденная укладка согласована с `OCCUPIED`; `DONE` не удерживает активные резервации/команду; `SAFE_STOP` не имеет active command и сохраняет резервацию при грузе; каждая дуга принадлежит `TRANSITIONS`.

Отдельный AST-аудит проверил шесть production Python-модулей controller: запрещённых imports evaluator/ground-truth и обращений к evaluator-only атрибутам не обнаружено. Контрактный тест отклоняет evaluator-only placement evidence. Входы M6 — M4 оценки, измеренное состояние руки/захвата, структурированный M5 результат и публичные сигналы; внутренний статус `PLACED_CONTROLLER_CONFIRMED` не равен истине оценщика. Статический аудит не является формальным доказательством изоляции будущего M7 adapter; сквозной аудит повторяется в M7.

## 7. Controlled verification и покрытие

Итоговый `run_m6_verification.py` запущен в отдельном virtual environment на Python 3.12.10 с версиями зависимостей из `controller/requirements-verification.txt`. **76 тестов прошли:** 45 controller, 21 planning regression и 10 perception regression. Тестовые наборы детерминированы; случайность не используется, поэтому seed в trace — `null`. Машинный отчет фиксирует команды, длительности, коды выхода, версии пакетов, хэш verification requirements, хэши конфигурации/модели/исходников и проверки экспортов.

| Controlled sequence | Что подтверждает на уровне контракта |
|---|---|
| Номинальный цикл и один объект | Команды/плановые фазы, observed hold, public placement evidence, slot reservation→occupied, закрытие цикла и возврат к свежему кадру. |
| Пустая сцена, UNKNOWN, частичная сцена и ошибки камеры | Разделение empty/camera failure, требование distinct fresh frames, bounded retry и fail-closed. |
| Недостижимый/проблемный + нормальный объект | Освобождение reservation, отметка причины, ограничение попыток, отсутствие starvation следующего track. |
| Дубли и противоречивые track IDs | Совпадающие ID объединяются; конфликтующие копии не создают двойной учёт/захват. |
| Все slots заняты / конфликты слотов | До движения отсутствуют фиктивная укладка и планирование в недоступное место. |
| Grasp failure, stale/unknown hold, loss при transfer, release/placement timeout | Границы достоверности, bounded recovery, quarantine и SAFE_STOP вместо ложного успеха. |
| Planner retries и повреждённые M5 планы | Однократный retry только для transient классов; неверный порядок фаз или отсутствующий release marker запрещает движение. |
| E-stop, SAFE_STOP с/без payload, reset, batch/cycle timeout | Отмена движения, удержание закрытого захвата при грузе, сохранение причины и безопасный interlock reset. |
| Переходы | Для всех 39 разрешённых дуг указаны существующие behavioral test cases; четыре recovery edge из `DESCEND`, `GRASP`, `VERIFY_PLACE` и `RETREAT` имеют отдельные тесты отказа исполнителя/тайм-аута. Отдельный глобальный guard проверяет объявленные и запрещённые дуги. |

Сохранён один 46-событийный номинальный trace `M6_nominal_controlled_double.jsonl` с меткой `CONTROLLED_TEST_DOUBLE`. Он заканчивает один track статусом `PLACED_CONTROLLER_CONFIRMED`, `RED:0` — `OCCUPIED`, затем FSM возвращается в `OBSERVE`. Эта трасса иллюстрирует политику тестового сценария; она **не** является результатом MuJoCo dynamics, физического теста или M9 trial и из неё не вычисляется sorting success rate.

State handler coverage подтверждает прямые behavioral tests для всех 16 states. `transition_coverage.csv` машинно сверена с `TRANSITIONS`, все 39 строк имеют `Behavioral path=Да` и ссылку на существующий test case; таблица состояний совпадает с enum; error matrix содержит 20 уникальных ID; draw.io state IDs совпадают с enum; flowchart содержит все 9 шагов pipeline. Исключительные дуги перечислены в нормативной таблице переходов и coverage CSV, тогда как рисунок специально оптимизирован для читаемого основного цикла.

## 8. Ошибки, обнаруженные и исправленные в M6

- `VERIFY_HOLD` попадал в общий исполнительный handler: выделена отдельная обработка, чтобы проверка выполнялась после завершения `LIFT` и свежих публичных сигналов.
- Общая логика входа в исполнительное состояние затеняла инициализацию `VERIFY_HOLD`: порядок dispatch исправлен.
- При отказах без возможного груза могли остаться track/slot reservations: теперь они освобождаются до recovery/reselection; при неопределённом или удерживаемом грузе остаются защищёнными.
- Счётчик recovery мог переноситься на новый подтверждённый recovery episode: после безопасного завершения budget сбрасывается.
- Устаревший hold signal мог интерпретироваться как актуальное отрицательное evidence: добавлена проверка возраста; timeout с неизвестным состоянием заканчивается SAFE_STOP.
- План M5 проверялся недостаточно строго для порядка фаз/event markers: добавлен полный preflight до первой команды движения.
- В тестах не были явно закреплены composite selection и детерминированный tie-break: добавлены отдельные регрессионные случаи.
- Четыре recovery-перехода имели только graph-guard или неподходящее общее покрытие. Добавлены прямые проверки отказа исполнения на `DESCEND`, `GRASP`, `RETREAT` и timeout в `VERIFY_PLACE`; генератор теперь отклоняет отсутствие behavioral case на любой разрешённой дуге.
- Первичный runner запускался в глобальном Python без установленного `mujoco`, поэтому завершился до suite и не сформировал пригодный отчет. Добавлены воспроизводимый `requirements-verification.txt`, инструкции отдельного venv и фиксация версий пакетов/хэша зависимостей; финальный повторный запуск в изолированной среде завершился успешно.
- Диаграмма показывала только выход к RETREAT без обратной дуги цикла: добавлен маршрут `RETREAT → OBSERVE`; генератор проверяет основной cycle path против state model.
- Первичная попытка экспорта draw.io не создала файл, потому что PowerShell не ожидал завершения GUI-процесса. Экспорт повторён через ожидаемый скрытый процесс; получены валидные PNG/SVG/PDF. Подпись на длинной возвратной дуге убрана после визуальной проверки.

## 9. Ограничения и handoff M7/M9

1. На M6 нет renderer/executor, реального контакта конечной геометрии, динамического удержания, фактического времени переноса или теста столкновений. Test doubles проверяют контракт принятия решений, не физику.

3. Семантика `safety_hold_requested`, отмены команды и точной корреляции `command_id` должна быть реализована и проверена исполнительным адаптером M7.

5. Selection weights, placement confidence и watchdog budgets — параметры M6 design-assumption. Их пригодность для полного динамического цикла должна быть подтверждена/скорректирована M7 и заморожена до M9 acceptance campaign.
6. M6 не закрывает риски контакта/трения, допуска по вертикальному ходу J3, целевого ПК и выборки M9.

**Блокирующей проблемы для начала M7 нет.** Граница адаптеров задана в `Контракт_M7_исполнения.md`; отсутствие placement camera adapter — ожидаемая работа M7, а не основание переписывать FSM. M9 campaign не начиналась.
