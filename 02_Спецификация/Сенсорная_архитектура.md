# Сенсорная архитектура

**Актуальная сенсорная конфигурация M7:** две фиксированные виртуальные RGB-камеры с разными назначениями, сигналы состояния приводов и контакта пальцев поступают через отдельные адаптеры. Реальные камерные модули не выбираются. Решение M1 об одной верхней камере сохранено для обнаружения входных объектов; в M7 к нему добавлен отдельный публичный вид лотков, потому что ROI входной камеры не наблюдает зоны сортировки.

## Сравнение вариантов

| Вариант | Оценка для этой задачи | Решение |
|---|---|---|
| Чтение истинного цвета/координат/ID из движка | Дает идеальный ответ, но исключает из проверки определение цвета и положения | Запрещено контроллеру; оставить только генератору и независимому оценщику |
| Скалярный виртуальный датчик цвета | Может классифицировать объект, но не дает достаточно содержательной оценки положения и ориентации для выбора и захвата | Не выбран как основной сенсор |
| Верхняя виртуальная RGB-камера | Дает изображение объектов во входной области для оценки цвета, XY и видимой ориентации | **Выбрана в M1** как вход perception; сохранена в M7 как `overhead_rgb` |
| Отдельная фиксированная RGB-камера лотков | Наблюдает выходные зоны после безопасного отхода манипулятора и позволяет проверить размещение публичным perception | **Добавлена в M7** как `placement_rgb`; не получает simulator truth и использует RGB-процессор с отдельной калибровкой |
| RGB-D | Может дать дополнительную глубину, но все предметы лежат на известной плоскости и имеют одну высотную группу | Не требуется в базовом объеме; добавление только при доказанной проблеме RGB и изменении решения |

## Установка и ориентация

`overhead_rgb` жестко закреплена сверху для наблюдения входной области. `placement_rgb` — отдельная фиксированная камера над лотками с направлением на сортировочную область. В M7 обе камеры возвращают синхронизированные RGB-кадры `640×480×3`, тип `uint8`, с согласованными `frame_id` и simulation timestamp. M1-размер `480×640×3` был проверкой API и не является размером интегрированных M7 камер.

Камеры неподвижны относительно рабочей ячейки. Для `overhead_rgb` M4 использует отдельную planar calibration для верхней грани входного объекта `z=0.016 m`; для `placement_rgb` M7 использует отдельную калибровку плоскости верхней грани объекта в лотке `z=0.020 m`. Калибровки, ROI и параметры обзора не взаимозаменяемы. Перекрытия звеньями учитываются как потеря видимости; подтверждение лотка запрашивается после M5 retreat, а не через чтение скрытого состояния.

## Данные, доступные контроллеру

Сенсорный адаптер возвращает только:

- сырой rendered RGB-кадр;
- timestamp в симуляционном времени и флаг валидности/устаревания;
- метаданные калибровки камеры из конфигурации, если они объявлены доступными;
- состояние собственных суставов/приводов через отдельный интерфейс;
- разрешенные показания контактного сенсора пальцев после их явной реализации.

Обработка обоих RGB-представлений выполняется одним и тем же perception-кодом с конфигурацией и калибровкой соответствующего вида. Модуль выдает собственные детекции, оценки класса/цвета, XY, ориентации, confidence и причину UNKNOWN/отказа. Передача готовой segmentation mask, истинной pose, simulator object ID или поля класса запрещена. Для лотков контроллер использует только `placement_rgb` и публичную perception-оценку класса/зоны/слота; evaluator-only ground truth остается отдельным.

## Независимая оценка

Независимый оценщик отдельно использует ground truth симулятора для сравнения фактического цвета, координат, класса зоны, контакта и результата укладки. Оценщик отделен от входов контроллера; его интерфейс направлен в оценочную подсистему и не имеет обратной связи в управляющий контур. Контроллер не получает результаты оценки.

## Ограничения

Обе камеры являются идеализированными виртуальными датчиками; проверка калибровки подтверждает проекцию в модели, а не реальную оптику. Входной верхний вид может перекрываться рукой; размещение подтверждается отдельным видом лотков после отхода. RGB-класс зависит от виртуального освещения, материалов и фона, а planar mapping применим только к утвержденной высоте. M7 проверил интеграционные случаи; разнообразие сцен, чувствительность и частота ошибок принадлежат приемочной кампании M9.
