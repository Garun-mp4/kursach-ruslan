# Прямая и обратная кинематика SCARA R–R–P–R

## 1. Назначение и границы

Документ фиксирует математическую модель манипулятора из геометрического baseline `M2-v1.0` и правила расчетов, добавленные в `M3-v1.0`. Все геометрические величины читаются из `параметры_системы.yaml`; модуль кинематики не содержит копий длин звеньев и смещений. Собственный FK/IK не вызывает решатель MuJoCo. Движок используется отдельным проверочным сценарием только как независимая сторона сравнения.

Результаты M3 доказывают кинематическую достижимость отдельных TCP-поз в рамках заданных координат и лимитов. Они не доказывают свободный от столкновений путь, достаточный зазор полного объема захвата, контактную надежность или физическую точность модели. Эти проверки принадлежат M5 и последующим этапам.

## 2. Суставный вектор, система координат и параметры

Порядок суставного вектора:

\[
q = [q_1, q_2, q_3, q_4]^T
= [q_1\;(rad),\ q_2\;(rad),\ q_3\;(m),\ q_4\;(rad)]^T.
\]

`BASE` — правая декартова система в основании робота; `WORLD` совпадает с `BASE` в нулевом смещении основания. Положительные вращения J1, J2 и J4 идут вокруг +Z. Положительное движение J3 направлено вниз, вдоль локальной оси −Z. Для вращательных суставов отдельные угловые offsets не заданы: `q` совпадает с координатой MuJoCo joint, у которого reference по умолчанию равен нулю. Это относится только к нулю угла; пространственные смещения между кадрами не нулевые и перечислены ниже.

| Параметр | Значение |
|---|---:|
| Длина звена L1 | 0,230 m |
| Длина звена L2 | 0,200 m |
| Высота плеча | 0,190 m |
| Центр J4 относительно каретки J3 | (0, 0, −0,075) m |
| TCP относительно J4 | (0, 0, −0,012) m |
| J1 | [−π, +π] rad |
| J2 | [−150°, +150°] |
| J3 | [0, 0,097] m |
| J4 | [−π, +π] rad |
| TCP при q3 = 0 | z0 = 0,103 m над BASE XY |
| Период симметрии квадратного объекта | π/2 rad |

TCP расположен на оси инструмента ниже J4. При q3=0 его высота равна `0,190 − 0,075 − 0,012 = 0,103 m`; поэтому `z_TCP = 0,103 − q3`.

## 3. Соглашение о преобразованиях

Используются однородные матрицы 4×4, векторы-столбцы и композиция слева направо по цепочке от основания к инструменту. Обозначения `Txyz(x,y,z)` и `Rz(θ)` — матрицы переноса и вращения вокруг Z. Трансформационная цепь:

\[
{}^{B}T_{TCP} = {}^{B}T_{J1}\,{}^{J1}T_{J2}\,{}^{J2}T_{J3}\,{}^{J3}T_{J4}\,{}^{J4}T_{TCP},
\]

где

\[
{}^{B}T_{J1}=T_{xyz}(x_b,y_b,z_b+0{,}190)R_z(q_1),\quad
{}^{J1}T_{J2}=T_x(0{,}230)R_z(q_2),
\]
\[
{}^{J2}T_{J3}=T_x(0{,}200)T_z(-q_3),\quad
{}^{J3}T_{J4}=T_z(-0{,}075)R_z(q_4),\quad
{}^{J4}T_{TCP}=T_z(-0{,}012).
\]

Смещение основания `(xb,yb,zb)` берется из SSOT. В текущей конфигурации XY-ноль основания и все суставные offsets равны нулю.

## 4. Прямая кинематика

Из произведения матриц получаем положение и yaw TCP:

\[
x = x_b + L_1\cos q_1 + L_2\cos(q_1+q_2),
\]
\[
y = y_b + L_1\sin q_1 + L_2\sin(q_1+q_2),
\]
\[
z = z_b + 0{,}103 - q_3,
\qquad \psi = wrap_{[-\pi,\pi]}(q_1+q_2+q_4).
\]

`forward_kinematics` отдельно формирует матрицы для `BASE`, `J1`, `J2`, `J3`, `J4` и `TCP`. Для FK координаты обязаны лежать внутри физических лимитов; выход за лимит не исправляется скрытым angle wrapping.

### Аналитический якобиан задачи

Для задачи `[x,y,z,ψ]` относительно `[q1,q2,q3,q4]` используется:

\[
J(q)=\begin{bmatrix}
-L_1\sin q_1-L_2\sin(q_1+q_2)&-L_2\sin(q_1+q_2)&0&0\\
 L_1\cos q_1+L_2\cos(q_1+q_2)& L_2\cos(q_1+q_2)&0&0\\
0&0&-1&0\\
1&1&0&1
\end{bmatrix}.
\]

Единицы строк: m, m, m, rad; единицы столбцов: rad, rad, m, rad. Диагностика обусловленности выполняется только для плоского XY-блока 2×2, поэтому смешение translational и angular единиц в condition number не происходит.

## 5. Аналитическая обратная кинематика

Для целевой позы `(x,y,z,ψ)` относительно основания вычисляется:

\[
c_2=\frac{(x-x_b)^2+(y-y_b)^2-L_1^2-L_2^2}{2L_1L_2},
\quad q_2^{(+)}=+\arccos c_2,\quad q_2^{(-)}=-\arccos c_2,
\]
\[
q_1=atan2(y-y_b,x-x_b)-atan2(L_2\sin q_2,L_1+L_2\cos q_2),
\quad q_3=z_b+0{,}103-z,
\quad q_4=\psi_{resolved}-q_1-q_2.
\]

Каждая из двух ветвей локтя обрабатывается отдельно. Геометрически невозможные `c2` отклоняются. Допускается лишь численный выход за `[-1,1]` в пределах `1e−12`; только такой round-off clamp может быть применен, и он отражается в `numeric_boundary_adjustment`. `q2` не циклически приводится к допустимому диапазону: ветвь, нарушающая физический лимит, отбрасывается. Для вращательных J1/J4 enumerируются периодические представители, и сохраняются только значения внутри реальных лимитов.

Для симметричного квадратного объекта период ориентации `π/2`: при включенной симметрии рассматриваются четыре эквивалентных yaw (`ψ+kπ/2`, k=0…3). При выключенной симметрии решается точная ориентация инструмента. Это свойство используется только тогда, когда объект и операция действительно допускают поворот на четверть оборота.

### Проверка ограничений и статусы

`IKResult` содержит статус, объяснение, все admissible candidates, выбранный candidate и FK-остатки.

| Статус | Значение |
|---|---|
| `SUCCESS` | Поза решена с остатками в заданном допуске |
| `NEAR_SINGULARITY` | Поза достижима, но локальная чувствительность повышена; не является отказом |
| `UNREACHABLE_GEOMETRY` | XY выходит за геометрический annulus звеньев |
| `JOINT_LIMIT_VIOLATION` | Геометрическое решение есть, но ветви не проходят пределы суставов |
| `Z_LIMIT_VIOLATION` | Требуемый ход J3 вне физического диапазона |
| `ORIENTATION_UNREACHABLE` | Нет значения J4, удовлетворяющего пределам и yaw |
| `INVALID_TARGET` | Неверная длина/тип вектора или неfinite координаты цели |
| `CURRENT_CONFIGURATION_INVALID` | Опорное состояние отсутствует, повреждено или нарушает limits |
| `NUMERICAL_FAILURE` | После аналитического решения независимый FK-остаток превышает acceptance tolerance |

При выходе более чем на численный допуск никакое решение не принимается: цель отклоняется. Случайный unit-test fault injection искусственно возмущает FK transform и проверяет, что результат становится `NUMERICAL_FAILURE`, а не успехом. В базовой конфигурации J4 имеет полный оборот ±π, поэтому отдельная ошибка ориентационных пределов не ожидается; тест с ограниченным временным диапазоном J4 подтверждает корректную классификацию такого случая.

### Выбор ветви

Для каждого кандидата вычисляется квадрат безразмерного расстояния от опорной конфигурации:

\[
C(q)=\sum_i\left(\frac{q_i-q_{i,current}}{q_{i,max}-q_{i,min}}\right)^2.
\]

Если `current_q` не передан, используется заданная SSOT safe-observation поза. Метры и радианы сначала нормируются на допустимый полный ход соответствующего сустава, поэтому они не складываются как величины разных размерностей. После цены применяются детерминированные tie-break: regular перед near-singular при равной цене, больший минимальный нормированный запас до лимита, порядок ветвей, индекс ориентационной симметрии, лексикографический вектор q. Эта политика выбирает локально близкий point solution; непрерывность целой траектории остается задачей M5.

## 6. Сингулярности

Плоский XY-якобиан теряет ранг при `sin(q2)=0`: вытянутой конфигурации `q2=0` и сложенной `q2=±π`. Для физического диапазона J2 `[-150°,150°]` вытянутая конфигурация доступна, сложенные — за пределами лимитов.

Near-singular diagnostic SSOT: `|sin(q2)|≤0,05`. Он не запрещает решение. На границе `q2=0,05 rad (2,86479°)` измерены `σ_min=0,00484938 m/rad`, XY condition number `97,7631` и локальное усиление обратного отображения `206,212 rad/m`. Поэтому небольшая ошибка XY около почти прямой руки может давать заметное изменение суставного решения; последующие планирование и управление должны учитывать это.

## 7. Зафиксированные численные допуски

Численные значения хранятся в SSOT `kinematics.*` и используются кодом до выполнения основного набора проверок.

| Параметр | Значение | Назначение |
|---|---:|---|
| `numeric_cos_tolerance` | `1e−12` (безразмерный) | Только round-off для `cos(q2)` |
| `joint_limit_tolerance_rad` | `1e−12 rad` | Представление R-кандидата у физической границы |
| `joint_limit_tolerance_m` | `1e−12 m` | Представление J3 у границы |
| `candidate_dedup_tolerance` | `1e−12` (нормированный) | Удаление повторов суставных решений |
| `position_acceptance_m` | `1e−6 m` | Приемка FK-позиционного остатка |
| `yaw_acceptance_rad` | `1e−8 rad` | Приемка yaw-остатка, учитывая симметрию, если разрешена |
| `near_singular_abs_sin_q2` | `0,05` | Диагностический порог, не запрет |
| Jacobian finite difference | `1e−7` | Шаг центральной разности в проверке производных |

Позиционный допуск — 0,001 mm, то есть численный допуск аналитической математики; он не является требованием к зрению, калибровке, физической точности или захвату. Код дополнительно проверяет результат выбранного кандидата и возвращает `NUMERICAL_FAILURE`, если позиционный или yaw остаток превышает acceptance.

## 8. Рабочая область

Для звеньев `L1=0,230 m`, `L2=0,200 m` свободная геометрическая радиальная область равна:

\[
|L_1-L_2|=0{,}030\;m \le r \le L_1+L_2=0{,}430\;m.
\]

При лимите J2 ±150° точная внутренняя граница увеличивается до `0,11500288 m`; внешняя остается `0,430 m`, так как q2=0 допустим. Диапазон TCP по высоте, обусловленный J3: `0,006…0,103 m`. J1 и J4 имеют полный оборот; все task orientations, используемые в тесте, представлены проверенными допустимыми q1/q4 кандидатами.

Проверены четыре прямоугольные области центров объекта/слотов на соответствующих высотах: зона подачи `0,24×0,16 m` при `z=0,008 m`, три лотка `0,16×0,16 m` при `z=0,012 m`. На каждую область наложена сетка 31×31 (961 точка), итого 3 844 точек; IK отказов нет. Все 15 центров отдельных слотов достижимы; максимальный позиционный остаток — `7,8811e−17 m`. Расчетная карта построена из параметров/вычисленных допустимых состояний, а не нарисована вручную.

**Это карта точечной кинематической достижимости TCP. Она не учитывает размеры захвата, звеньев, лотков/препятствий, самостолкновения или прохождение между целями; она не является картой collision-free поз и путей.** M5 должен отдельно проверять коллизии геометрии и траекторий, а M7 — интегрированную физическую модель.

## 10. Ограничения и передачи следующим этапам

- Точная кинематика строится по параметрической идеальной геометрии; люфты, деформация, приводная ошибка и калибровка не моделируются.
- IK решает pose-to-point задачу без оптимизации времени/ускорений и без проверки пути.
- При nearly straight J2 задача плохо обусловлена; M5/M6 должны избегать или контролировать такие конфигурации в траектории/управлении.
- Карта workspace относится к точке TCP; полный объем пальцев и звеньев не включен.
- Входная зона и три лотка кинематически доступны, но реальный безколлизионный цикл сортировки еще не подтвержден.
- Pick TCP z=0,008 m соответствует `q3=0,095 m`, оставляя только 2 mm до верхнего предела J3=0,097 m. Кинематически это достижимо, но бюджет на погрешности датчика/контактную геометрию и интегрированную устойчивость должен быть проверен M4/M7.
