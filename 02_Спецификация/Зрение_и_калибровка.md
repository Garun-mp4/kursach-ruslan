# Компьютерное зрение и калибровка камеры — M4

**Проект:** моделирование и симуляция SCARA-манипулятора для сортировки объектов по цвету  
**Версия профиля:** `M4-v1.3`  
**Калибровка:** `M4-HOMOGRAPHY-TOP-PLANE-v1.1`  
**Дата независимого прогона:** 25.09.2026  
**Статус:** perception subsystem проверена в виртуальном стенде; планировщик, FSM и полный цикл сортировки на этом этапе не реализуются.

## 1. Роль модуля и граница данных

Поток M4 состоит из рендерера виртуальной камеры, минимального адаптера кадра, perception и отдельного независимого оценщика:

```text
MuJoCo Renderer → CameraFrame (RGB, uint8, время, validity, camera ID)
               → perception (кандидаты, класс, поза, качество/причина)

MuJoCo ground truth → только evaluator → метрики и диагностические манифесты
```

`CameraFrame` не содержит имя/ID объекта, истинный цвет, истинную позу, маску сегментации или ссылку на `MjData`. Runtime-пакет `04_Программа/perception/` не импортирует MuJoCo, стенд, evaluator или ground-truth типы. Статический AST-аудит зафиксировал 0 нарушений. Истинные метки и позы попадают только в отдельные evaluator-манифесты; управляющий интерфейс их не читает.

## 2. Камера и сенсорный интерфейс

Используется верхняя RGB-камера M2 без изменения геометрии: положение `[0, 0, 1.05] m`, ориентация MuJoCo quaternion `[1, 0, 0, 0]` (`wxyz`), вертикальный FOV `50°`, изображение `640 × 480 px`, расчётные внутренние параметры `(fx, fy, cx, cy) = (514.6816609, 514.6816609, 319.5, 239.5) px`. Кадр имеет начало координат в левом верхнем углу, `u` растёт вправо, `v` — вниз; система координат результата — BASE, метры.

Контракт `CameraFrame`: RGB `uint8`, ширина/высота, frame ID, simulation timestamp, validity, camera configuration ID. Максимальный возраст кадра — `0.04 s`. При отсутствии кадра возвращается `NO_FRAME`; устаревший — `STALE`; неверный размер/тип, несовпадающий camera ID или будущее время — `INVALID`. Для любого такого случая batch не содержит детекций, поэтому предыдущая поза не переиспользуется.

Проверка каналов выполнена и на синтетических RGB-примерах, и на реально отрендеренной сцене MuJoCo. RGB красного контрольного участка дал средние каналы `[254.64, 65.80, 57.92]`; доминирует R. OpenCV преобразует вход явно через `COLOR_RGB2HSV`; при сохранении RGB-кадра через `imwrite` выполняется преобразование RGB→BGR. Синтетические красный/зелёный/синий образцы дали ожидаемые HSV Hue `0/60/120` в шкале OpenCV `0…179`. Это важно, потому что стандартный порядок байтов OpenCV часто BGR; он задаётся явно в API [OpenCV: Color Space Conversions](https://docs.opencv.org/doc/doxygen/html/d8/d01/group__imgproc__color__conversions.html). Рендеринг выполняет официальный offscreen renderer MuJoCo [MuJoCo: Code samples / render](https://mujoco.readthedocs.io/en/latest/programming/samples.html).

## 3. Рабочая область и геометрическая модель

Калибровка и локализация относятся к верхней плоскости куба M2 высотой `16 mm`: `z_top = table_top_z + object_height = 0.016 m`. Размер квадрата — `28 × 28 mm`. Положение иных высот или штабелированных объектов из этой гомографии не выводится.

Детектор ищет объекты только внутри входной ROI M2: `x ∈ [−0.145, 0.145] m`, `y ∈ [−0.355, −0.145] m`. Три зоны сортировки исключены полигональной ROI, построенной через ту же калибровку. Проверка каждой зоны RED/GREEN/BLUE дала ноль кандидатов.

Сопоставление pixel→BASE является плоской гомографией, а не общей 3D-проекцией и не ray-plane алгоритмом. 49 калибровочных точек задают матрицу; 64 отдельные точки по центру, краям и углам к ней не подмешивались. Точки задавались в BASE, маркеры обнаруживались в RGB изображении. Номинальная M2 intrinsics использована лишь для однозначного сопоставления видимых маркеров с координатами калибровочной сетки; сама матрица гомографии оценена по детектированным центрам маркеров и их известным координатам. Для преобразований использованы `findHomography` и `perspectiveTransform` OpenCV [OpenCV: Homography](https://docs.opencv.org/4.x/d7/dff/tutorial_feature_homography.html).

Координатные соглашения, camera pose, размеры, зоны, BASE и M2 параметры подтверждены сборкой/валидатором SSOT. SHA-256 модели MJCF сохранился: `d5445d8a6a4cf1a38f533be697d6cd0748d457e4de40d6a16d5240752957c9e2`.

## 4. Обнаружение кандидатов, цвета и отказов

Кандидат формируется сравнением текущего кадра с неизменным фоном в пространстве CIE Lab: пиксель попадает в первичную маску при `ΔE*ab ≥ 16`. Перед сравнением применяется поканальная нормализация освещённости по медиане статического фрагмента стола, ограниченная gain `[0.55, 1.8]`. Маска ограничена входной ROI, очищается морфологическими ядрами `3 × 3`, после чего извлекаются внешние контуры. Геометрические пределы: площадь `8…520 px²`, отношение длинной стороны к короткой `0.45…2.2`; номинальная проекция предмета — `194 px²`.

Цветовая классификация выполняется по HSV внутри эродированного контура, чтобы меньше учитывать границу и стол. Утверждённые диапазоны (S/V — 8-bit шкала OpenCV):

| Класс | Hue, OpenCV 0…179 | S min | V min |
|---|---:|---:|---:|
| RED | `0…7` **или** `176…179` | 155 | 231 |
| GREEN | `57…69` | 156 | 231 |
| BLUE | `108…121` | 157 | 231 |

Два Hue интервала RED учитывают циклический переход Hue через границу шкалы. Неподдерживаемый оттенок получает класс `UNKNOWN`, а не ближайший из трёх целевых цветов. Для каждого кандидата `confidence` вычисляется как произведение доли пикселей доминирующей маски и ограниченного margin между лучшим и следующим цветовым score; это согласованный score, **не вероятность**. Порог score — `0.36`, минимальный class margin — `0.22`. Сам класс `UNKNOWN` не даёт разрешения на захват, даже если контур и координата геометрически валидны.

Оценка качества pose отдельна от класса. `status=VALID` говорит о пригодной геометрии в объявленной модели, но будущий controller всё равно обязан проверять `class_label ∈ {RED,GREEN,BLUE}`. Кандидат с низкой видимой площадью, недопустимой формой, крупным/слившимся контуром или невозможностью надёжного разделения помечается `OCCLUDED` с причиной; неизвестный цвет остаётся `UNKNOWN`. Крупный связанный контур разделяется только если RGB-маски дают минимум два отдельных геометрически допустимых ядра известных классов; иначе он отклоняется. Произвольные кучи не разделяются.

## 5. Центр, ориентация и трекинг

Для цвета, уверенно отнесённого к одному из RED/GREEN/BLUE, центр оценивается как центр минимального охватывающего прямоугольника выделенного цветового ядра (`color_core_rect_center`). Отдельно измерены альтернативы: centroid маски, центр прямоугольника внешнего контура и centroid цветового ядра. Перенастроенная метрика M4 хранит их все в CSV; настройка центра зафиксирована до независимого набора.

Yaw вычисляется по длинной стороне минимального прямоугольника контура, уже преобразованного в BASE XY. Квадратный объект имеет симметрию четверти оборота: угол канонизируется в `[0, π/2)`, а ошибка оценивается по модулю `π/2`; поворот на 90° не считается ошибкой захвата.

Межкадровые ID создаёт локальный детерминированный nearest-neighbour tracker по XY с совместимостью классов. Радиус сопоставления `0.055 m`, удержание при пропуске до 2 кадров. В тесте малого сенсорного шума два наблюдения сохранили track IDs `1,2`; внутренние ID симулятора не используются.

## 8. Независимая оценка и результаты

Оценщик сопоставляет оценки и истины взаимно-однозначно ближайшим расстоянием XY не более `25 mm`. Это окно относится только к подсчёту object detection; оно не является допуском захвата. Несопоставленные истины остаются false negatives и в знаменателе recall. Матрица цвета включает `UNKNOWN` и отдельный столбец `NO_DETECTION`.

### Обнаружение и классификация

На независимой выборке: `TP=368`, `FP=0`, `FN=0`, precision=`1.000`, recall=`1.000`, F1=`1.000` по принятому 25 mm matching. Переклассификаций между RED/GREEN/BLUE нет; `UNKNOWN → supported color` нет. Объектов истинных классов RED/GREEN/BLUE/UNKNOWN было соответственно `114/119/120/15`; все 15 неизвестных остались `UNKNOWN`. Три низкоконтрастных объекта находятся вне объявленной видимости и получили статус `OCCLUDED`; они не являются разрешёнными целями захвата. Все данные сохраняются, включая каждый пропуск/отказ.

### Локализация и ориентация

Метрики координат рассчитываются отдельно от detection/classification. Из 368 результатов `365` имели позу в status `VALID` (353 целевых цвета и 12 геометрических поз UNKNOWN); 3 позы были `OCCLUDED` и не участвуют в ошибке захвата.

| Метрика | Все 365 поз | Только сортируемые классы, n=353 | M2 бюджет/предел |
|---|---:|---:|---:|
| XY mean | 0.476 mm | 0.437 mm | — |
| XY median | 0.398 mm | 0.394 mm | — |
| XY p95 | 1.042 mm | 0.891 mm | perception allowance 2.000 mm |
| XY max | 2.178 mm | 1.361 mm | 2.000 mm allocation |
| Yaw p95 | 3.941° | 4.019° | 10.000° |
| Yaw max | 6.647° | 6.647° | 10.000° |

Два XY остатка больше `2 mm` принадлежат классу UNKNOWN; ни один из 353 объектов целевых классов не вышел за выделенный M4 XY budget. UNKNOWN никогда не превращается в цель сортировки: будущий исполнительный слой должен проверять и `status`, и `class_label`. Поэтому для заявленных цветовых pick-целей accuracy достаточна; статистический p95 и максимумы сохранены, а превышение для диагностических UNKNOWN не скрыто. Общий M2 XY бюджет — `4 mm`; измеренный p95 восприятия занимает `1.042 mm`, оставляя по арифметическому разбиению `2.958 mm` на последующие геометрические/исполнительные вклады. Это не заменяет проверку контакта и суммарного захвата M7.

### Error budget и чувствительность

| Источник | Оценка/наблюдение | Интерпретация |
|---|---|---|
| Дискретизация пикселя | На плоскости `z=16 mm`, глубина `1.034 m`: около `2.009 mm/px`; половина пикселя ≈`1.004 mm` на ось, ≈`1.421 mm` радиально | Верхняя оценка для точечного пикселя; contour/core геометрия использует субпиксельные моменты и усредняет много пикселей |
| Оценка центра | Для целевых объектов выбранный color-core rectangle: p95 `0.891 mm`, максимум `1.361 mm`; альтернативные оценки отдельно лежат в `localization_errors.csv` | Выходное XY одновременно зависит от качества маски и доступной цветовой области |
| Гомография | Независимая validation: p95 `0.512 mm`, максимум `0.879 mm` | Не складывать напрямую с полной XY ошибкой: итоговая оценка уже измеряет комбинированный pipeline |
| Высота предмета | Точно задана моделью: `16 mm`, homography относится к top-face plane | При неучтённом отклонении высоты на `±1 mm` масштабная ошибка на границе входной области оценивается примерно до `0.37 mm` радиально; штабелирование/другие высоты не входят в модель |
| Оценка yaw | Симметричная метрика modulo `π/2`; максимум `6.647°`, p95 `3.941°` | Ниже M2 предела `10°` для виртуальных целевых классов |
| Изображение/освещение | Независимо проверены brightness factors `0.75…1.25`, RGB noise `σ=0…3`; 36 пустых сцен дали 0 ложных кандидатов | Это искусственная модель рендерера, не измерение сенсора камеры |

Итоговая XY ошибка измерена целиком, поэтому перечисленные слагаемые не следует механически складывать или объявлять независимыми вероятностными распределениями. Выходные `position_sigma_m=0.0015` и `yaw_sigma_rad=0.08` — конфигурационные allowance, а не калиброванные ковариации и не гарантированный worst-case bound.

## 12. Ограничения и передача в следующие этапы

Подтверждено только в программной модели: контролируемый MuJoCo renderer, матовые кубоиды, фиксированная overhead camera, статический фон, заданные материалы и одна известная top plane. Реальная камера, автоматическая экспозиция/баланс белого, блики, тени неизвестной формы, износ оптики, предметы вне плоскости, стопки и промышленные материалы не испытывались. Три почти белых низкоконтрастных UNKNOWN-примера находятся вне объявления visibility; их нельзя использовать для захвата.

Для M5 интерфейс отдаёт `class_label`, `xy_base_m`, `yaw_base_rad`, confidence, configured uncertainty, status/reason, frame/time и собственный track ID. Planner должен принимать только свежие `VALID` позы с поддержанным классом и ограничивать применимость заявленной ROI/плоскостью. M6 должен отдельно отказать/повторно получить изображение для `UNKNOWN`, `OCCLUDED`, `NO_FRAME`, `STALE` и `INVALID`. Этот документ не содержит траекторий, FSM или результатов полного цикла сортировки. Для M7 нужна повторная проверка с интегрированным роботом и реальной геометрией контакта.
