# Запись визуализации и телеметрия M8

**Версия:** M8-v1.0
**Связанные версии:** интеграция M7-v1.8, runtime schema M7-v1.1, SSOT M7-v1.8
**Область:** подготовка доказательной визуализации и логов для последующей приемочной кампании M9.

## 1. Назначение и границы

M8 добавляет к пакетному запуску необязательную запись того же физического прогона MuJoCo. Во время исполнения recorder снимает полное интеграционное состояние MuJoCo и открытые события контроллера по времени симуляции. После завершения контроллера отдельный зрительский renderer воспроизводит сохраненные состояния и формирует MP4 и контрольные кадры. Запись не рассчитывает действия, не подменяет RGB-камеры `overhead_rgb` и `placement_rgb`, не меняет шаг физики и не управляет FSM.

Контроллер и HUD получают только поля своего публичного состояния: FSM, активный track из записей M6, оцененный класс, число обнаруженных track и число размещений, подтвержденных контроллером. Ground truth, цвет из конфигурации сцены, тело объекта, приватный evaluator и результат физической оценки не передаются HUD или управляющему алгоритму. Записанный физический state stream хранится отдельно в `evaluator_private/recording/` и используется только для последующего изображения той же сцены.

Видео и виртуальные результаты не являются физическим испытанием. Демонстрационный запуск M8 не заменяет выборку и критерии приемки M9.

## 2. Настройки записи

| Параметр | Зафиксированное значение | Правило |
|---|---:|---|
| Контейнер | MP4 | Проверяется полным последовательным декодированием после записи |
| Кодек | H.264 `avc1`, если encoder доступен; иначе MPEG-4 Part 2 `mp4v` | Кодек фактически записывается в манифесте; звук не добавляется |
| Размер кадра | 1280 × 720 px | 16:9; основной ракурс 960 × 720, две боковые панели |
| Частота выходного видео | 25 кадр/с | Фиксированная частота кодирования |
| Скорость воспроизведения | номинально ×5 | Отношение simulation time к видео time указывается также фактически |
| Период отбора состояния | 0,2 s simulation time | `playback_speed / fps`; кратен control period 0,01 s и physics step 0,002 s |
| Начальный кадр | t = 0 | Снимается до первого вызова контроллера |
| Последний кадр | фактическое состояние окончания прогона | Добавляется вне сетки 0,2 s, если необходимо; короткий последний интервал не маскируется |
| Пропуск кадров | без дублирования; учитывается счетчиком | На штатном стенде состояния снимаются на управляющих тактах; все пропуски отражаются в manifest |

Сэмплирование основано на simulation clock. Wall-clock время рендера не используется как время симуляции или вход контроллера. Для штатного набора параметров период 0,2 s соответствует 20 циклам управления и 100 шагам физики. MP4 строится из сохраненных интеграционных состояний этого run, а не из независимой анимации.

## 3. Композиция кадра

* **Основной ракурс:** свободная камера зрителя показывает манипулятор, входную область и цветовые лотки.
* **Вид сверху:** независимая камера зрителя показывает расположение объектов и трех зон. Легенда подписывает `RED`, `GREEN`, `BLUE`; цвет не является единственным носителем информации.
* **Крупный план:** отдельная свободная камера следует за визуальным TCP/захватом.
* **HUD:** надпись «ПРОГРАММНАЯ СИМУЛЯЦИЯ», `run_id`, время симуляции, номинальное ускорение, состояние FSM, номер активного/последнего выбранного track, оцененный контроллером цвет и счетчик подтвержденных самим контроллером размещений среди обнаруженных track.

Эти три камеры предназначены только для наблюдения. Сенсорные RGB-вида остаются теми же, что использовались в реальном для модели цикле управления. Контрольные изображения `before_detection`, `detection`, `grasp`, `transfer`, `release`, `final`, `error_recovery` сохраняют state в момент соответствующего события. Отсутствующий этап не синтезируется: список реально полученных кадров хранится в манифесте.

## 4. Связь видеокадров с run и журналами

Для каждого запуска создается каталог `06_Медиа/проверка_записи/<run_id>/`, в котором лежат:

* `симуляция.mp4` — зрительский рендер сохраненных состояний;
* `кадры/*.png` — event-keyframes, построенные из тех же сохраненных состояний;
* `Запись_и_связанные_логи.json` — `run_id`, сценарий и seed, исходные хеши конфигурации/кода/модели, hash MP4 и state stream, FPS, разрешение, моменты начала и окончания simulation time, число записанных и декодированных кадров, codec, оцененная скорость воспроизведения, имена исходных журналов и их SHA-256, события и ближайший индекс кадра для каждого keyframe.

Неизменённый `source_run_manifest.json` также сохраняется рядом с приватным state stream, а его SHA-256 записывается в media manifest. Хешируются все файлы, перечисленные в `relative_outputs` исходного M7 run manifest: controller events/telemetry/perception snapshots, M5 plans (каждый файл отдельно), evaluator object telemetry, physics-step contact episodes и итоговый evaluator report. Отсутствующий перечисленный output считается ошибкой записи, а не пропускается.

Первичный state stream и снимок исходного run manifest хранятся в каталоге `05_Верификация/integration/runs/<run_id>/evaluator_private/recording/`. Зрительский рендер строится после завершения controller-run; он не изменяет первичные логи. Монтаж для презентации (если он появится позднее) хранится отдельно и обязан ссылаться на исходные `run_id` и диапазоны кадров/времени.

## 5. Контракт журналов для M9

| Файл | Содержание и ключи | Частота / единицы | Использование в M9 | Доступ управляющей логике |
|---|---|---|---|---|
| `manifest.json` | run ID, сценарий, seed, среда, версии, physics/runtime config, fault injection, хеши всех входов и summary | один документ/run | воспроизводимость и группировка запусков | метаданные не являются входом контроллера |
| `controller/controller_events.jsonl` | ID и тип события, sim time, state, причина, track/slot, details | событийная, simulation seconds | переходы FSM, попытки, причины отказа, длительность фаз | создается контроллером и runtime |
| `controller/telemetry.csv` | `actual_q/commanded_q` (rad, m), velocities (rad/s, m/s), accelerations, TCP (m/rad), gripper (m), touch/effort (N, Nm), phase/state | не реже 25 Hz при runtime `telemetry_period_s=0.04 s`; final row дополнительно | tracking error, TCP path/time, суставные пределы, усилия, фазы | значения фактического исполнения доступны runtime согласно M7 |
| `controller/perception_snapshots.jsonl` | input/placement view, frame ID/time/age, validity, resolution, batch status, detection class/confidence/XY/yaw/covariance | при запросе наблюдения и проверках размещения; событийная | precision/recall, UNKNOWN, локализация и возраст кадра после evaluator association | публичные RGB/perception results |
| `controller/plans/m5_plan_*.csv` и `.json` | фазы, joint/TCP trajectory, скорости/ускорения, payload mode, plan result | на запрос планирования | траектория, длительность, геометрический preflight/clearance по M5 данным | планирование получает M4 detections и публичные ограничения |
| `evaluator/object_telemetry.csv` | ground-truth цвет, свободная поза/скорость объекта, touch, bilateral contact, slip | около 25 Hz, SI units; одна строка на объект на выборку | независимая локализация, захват/удержание/скольжение, физическое размещение | только post-run evaluator; не является controller input |
| `evaluator/contact_events.jsonl` | уникальная пара geom, границы contact episode, длительность, минимум signed distance, максимум normal/tangent force, число physics samples | contact episode, обнаруживается каждый physics step; время в s, дистанция в m, силы в N | разбор динамических контактов/столкновений с дедупликацией непрерывного контакта | только evaluator |
| `evaluator/report.json` и `evaluator_private/scene_truth.json` | итоговая проверка сортировки и эталонные метки сцены | один отчет/run; ground truth отдельно | confusion/ошибки, успех по фактической зоне и условиям размещения | post-run; запрещено читать контроллеру |
| `evaluator_private/recording/state_stream.npz` + manifest | сериализованные `mjSTATE_INTEGRATION` states, время, UI-поля контроллера и события | 5 кадров/s simulation clock плюс exact terminal state и event keyframes | воспроизведение видеосвидетельства того же run | viewer-only после run; не передается в control loop |

События контакта сохраняются как **эпизоды пары геометрий**, а не как независимое столкновение на каждом контрольном такте. Для каждого эпизода M9 должен применять заранее описанный классификатор допустимых пар захвата/опоры и недопустимых контактов; длительный разрешенный контакт не следует считать множеством столкновений. Object/evaluator данные могут использоваться только независимым анализатором после run.

Контакт читается сразу после каждого `mj_step`. `start_time_s` обозначает начало первого физического интервала, на котором пара обнаружена; `end_time_s` — timestamp последнего шага, на котором пара присутствовала; `detected_closed_time_s` — timestamp первого следующего physics step без этой пары. Длительность задается числом положительных контактных physics samples × зафиксированный `physics_timestep_s`. Таким образом, время обнаружения закрытия не смешивается с оценкой длительности контакта.

Существующего лога достаточно для запланированных M9 показателей: распознавание/локализация — perception snapshots + evaluator truth; сортировка — независимый evaluator; суставная/TCP ошибка — runtime telemetry; длительность фаз — controller events; TCP path — telemetry; dynamic contact episodes — частотный physics-step монитор контактов; версии и воспроизводимость — manifest. Финальные допуски, знаменатели и правила сопоставления detection↔ground truth остаются предметом методики M9, а не результатом M8.

## 6. Одна команда и проверка

Из корня репозитория в PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) '04_Программа')
& '99_Рабочие_материалы/integration/.venv/Scripts/python.exe' `
  '04_Программа/run_m7.py' --mode batch --scenario single_red_center `
  --physics-profile nominal --record `
  --out '05_Верификация/integration/runs' `
  --recording-out '06_Медиа/проверка_записи'
```

После run проверяются: открытие MP4, полный sequential decode всех кадров, FPS/размер, равенство числа декодированных кадров числу состояний, последний timestamp/state с run summary, хеши source logs/state/config, наличие кадров, запускаемых событийными метками. H.264 `avc1` проверяется первым. В зафиксированной OpenCV-сборке проекта encoder OpenH264 отсутствует; поэтому проверенный рабочий fallback — `mp4v`. Этот фактический codec отмечается в manifest, формат не объявляется H.264.

Для технических smoke-прогонов с ограничением simulation time код завершения runner может быть ненулевым, если состояние контроллера не `DONE`; это не подменяется успешной приемкой. У штатной демонстрационной записи сохраняются полный run, его нормальный итог и независимый evaluator report. M8 не объявляет статистическую эффективность и не выполняет кампанию M9.

## 7. Ограничения визуального доказательства

Свободные камеры зрителя используют точное состояние модели для изображения; они не моделируют реальную камеру и не доказывают работу perception. Видео ускорено и не воспроизводит wall-clock скорость ПК. Выводы о правильной сортировке берутся из evaluator report и связанных журналов, а не из визуального впечатления или HUD. MP4 использует `mp4v`, поскольку `avc1` encoder недоступен в проверенной локальной OpenCV-сборке. Физический прототип, реальный захват и реальное зрение не проверялись.
