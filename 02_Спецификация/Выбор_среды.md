# Выбор симуляционной среды и Python-стека

**Решение M1:** основной движок — MuJoCo 3.14.0; версия Python — CPython 3.12.10 x64.  
**Проверка:** 24.09.2026 на Windows 11 x64, на рабочем ПК проекта.

## Критерии выбора

Для курсовой важны непосредственное управление шарнирными и поступательными координатами, контактная физика двух пальцев и объекта, RGB-рендер, пакетные детерминированные прогоны, доступ из Python, установка на Windows и получение видео из того же состояния физики. Среда должна поддерживать собственную учебную модель, чтобы не зависеть от неясного происхождения промышленного asset.

## Сравнение вариантов

| Среда | Возможности, установка и лицензия ядра | Решение |
|---|---|---|
| MuJoCo + Python | Официальные native Python bindings; MJCF; суставные и физические модели; offscreen rendering доступен через Renderer/OpenGL; для конкретной версии 3.14.0 опубликован CPython 3.12 Windows x64 wheel. Ядро MuJoCo имеет Apache-2.0. На этом ПК импорт, R/P-стенды, RGB-рендер, физический контакт пальцев, отпускание и MP4 прошли | **Выбрана**: минимальный разрыв между симуляцией, контроллером, логами и рендером; установка подтверждена в чистом venv |
| PyBullet + Python | Предоставляет физику, articulated models, кинематику, коллизии и DIRECT/TinyRenderer; PyPI указывает zlib/libpng license. В опубликованном списке release files 3.2.7 не найден Windows wheel для рассматриваемого CPython; доступен крупный source archive. Это создает риск необходимости локальной сборки | Отклонена как основной стек из-за переносимости/сборки на Windows, несмотря на привлекательный программный рендер |
| Webots | Полноценное настольное моделирование и официальная Windows-сборка; умеет моделировать робототехнические устройства и камеры; исходники ядра Webots публикуются под Apache-2.0 | Технически жизнеспособна, но отдельная среда и цикл контроллера сложнее упаковываются вместе с Python-кодом и пакетными экспериментами для ограниченной учебной модели; не нужна после успешной проверки MuJoCo |
| Gazebo | Широкая робототехническая интеграция и развитая экосистема; core gz-sim имеет Apache-2.0, однако состав сторонних компонентов среды нужно лицензировать отдельно | Для этой автономной курсовой дает лишнюю инфраструктуру; официальная Windows-документация на дату проверки называет поддержку экспериментальной и описывает сложную установку, поэтому не выбран |

Выбор не утверждает, что MuJoCo лучше в любой робототехнической задаче. Это решение для моделируемой стационарной ячейки, локальной работы на Windows и собственного Python-контроллера.

## Проверенная установка и версии

В новом изолированном окружении CPython 3.12.10 команда установки из requirements.txt завершилась успешно с Windows wheel. Зафиксированы прямые зависимости:

| Пакет | Версия | Роль M1 |
|---|---:|---|
| mujoco | 3.14.0 | Движок и Python API |
| imageio | 2.37.0 | Сбор RGB-кадров в видео |
| imageio-ffmpeg | 0.6.0 | Кодирование/декодирование MP4 для стенда |

Полный снимок зависимостей чистого окружения сохранен в requirements-lock.txt. Включать OpenCV до M4 не нужно: M1 не реализует распознавание. Нет обязательной зависимости от ROS, Arduino, облака, нейросетевых библиотек или GPU-вычислений.

## Производительность и переносимость

Проба выполнена на Windows 11 x64, Intel Core i5-11400H (6 ядер/12 потоков), 8 GB RAM, графике NVIDIA GeForce GTX 1650 Max-Q и Intel UHD; свободное место на момент замера составляло около 19.8 GiB. Offscreen RGB-рендер использовал native OpenGL-контекст графического драйвера и прошел на текущей машине без видимого GUI. GPU-вычисления симулятора не требуются, но графический контекст и совместимый драйвер необходимы. CPU software-render backend в выбранном Windows/Python окружении отдельно не установлен и не подтвержден; на поддержку software rendering не рассчитывать. Для защиты повторить установку/рендер на целевом ПК. Скорость упрощенного стенда не переносить на финальную модель.

Рекомендуемый способ запуска будущего проекта: Python 3.12 x64, отдельное виртуальное окружение, установка зафиксированных зависимостей из репозитория, относительные пути к собственному MJCF и данным. Возможность headless-render проверена на этой конфигурации, но не означает программный CPU-рендер.

## Лицензии и происхождение

Лицензии ядра сравниваемых сред сверены по официальным метаданным/репозиториям: MuJoCo — Apache-2.0; PyBullet — zlib/libpng; Webots — Apache-2.0; Gazebo core gz-sim — Apache-2.0. Это не означает, что все плагины, данные и транзитивные зависимости каждого набора имеют ту же лицензию: они требуют собственного инвентаря перед распространением. Стенд и собственные MJCF созданы внутри проекта; внешние модели роботов, меши и текстуры не загружаются. Лицензии фактически устанавливаемых Python-зависимостей и медиакодека будут окончательно включены в инвентарь M12.
